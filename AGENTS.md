# Reteno Android SDK — Agent Playbook

Android SDK in Kotlin (1.8.0, coroutines 1.6.4, AGP 8.1, Gradle 8.1). Modules: `RetenoSdkCore`, `RetenoSdkPush`, `RetenoSdkFcm`, sample `app`, and the test-only `RetenoSdkTestFixtures`.
The SDK is being refactored to one-file-per-operation Actions on coroutines; the plan and its decisions live in `docs/refactoring/coroutine-actions-plan.md`. Read it before touching an SDK flow.

## Hard constraints

- **Toolchain is frozen.** Do not bump Kotlin, coroutines, AGP or Gradle. No Kotlin 1.9+ features (`data object`, `entries`), no coroutines 1.7+ APIs (`TestScope.backgroundScope`, `runTest(timeout = …)`).
- **Stored data is frozen, DB code is not (plan D13).** Schemas, SQL, table/column names, stored value formats, migrations' effect and the `RetenoDatabaseManager*` interfaces and their behaviour stay unchanged for backward compatibility; implementation code (`RetenoDatabaseImpl`, manager impls, `DbUtil*`, local mappers) may be restructured for testability and to drop PII from logs. Actions call managers from `withContext(dispatchers.io)`.
- **Public API is frozen.** `Reteno`, `AppInbox`, `Recommendation`, `RetenoNotifications`, callbacks and public models stay source- and binary-compatible. Never add companions or members to public models for test convenience.
- **Removing anything public (even technically public internals) goes into `CHANGELOG.md`** under the next version's **Removed** section; behaviour changes integrators can notice go under **Changed** or **Fixed**.
- Run Gradle with **JDK 17** (what CI uses): `export JAVA_HOME=$(/usr/libexec/java_home -v 17)`. Gradle 8.1 cannot compile build scripts on newer JDKs and Robolectric 4.8.1 cannot read their class files.

## Core conventions

- **Never write comments** in new code (production or tests). Express intent through names: a `step("…")` name, an extracted function, a named value. Existing comments stay untouched. Exception: KDoc on public SDK API, which consumers read.
- New internal code lives under `com.reteno.core.internal.*` with `internal` visibility:
  - `internal.action.<feature>` — one Action per SDK operation
  - `internal.action.trace` — `ActionRunner`, `ActionTrace`, `TraceFormatter`, `ActionFailureReporter`, `MonotonicClock`
  - `internal.coroutine` — `RetenoDispatchers`, `retenoScope()`, `InitGate`
  - `internal.network` — `SuspendApiClient`, `ApiResult`
  - `internal.event` — `EventBus`
  - `internal.log` — `RetenoLogSink`, `AndroidLogSink`, `LogPriority`, `Redact`
- No `Executors`, `Handler` or `runBlocking` in new code (the legacy `OperationQueue` / `RetenoThread*` are deleted).
- No `Reteno.instance` / `Reteno.instanceInternal` / `SdkComponent` access inside SDK internals. Dependencies come through the constructor; Android facts (context, package info, telephony) come from the platform ports in `internal/platform`. The only singleton readers are the public entry points and the system entry points `PushDataWorker` and `RetenoInternalEntryPoint`.
- `di/SdkComponent` is the one composition root (plan D12): it owns the shared infrastructure (prefs, `RestConfig`, `RestClient`, `ConfigRepository`, `FileManager`, activity helper, session tracker, `DatabaseManagers`, `SdkConfiguration`, the permission delegate) as plain `by lazy` singletons and builds `ActionGraph`. The graph sees it only as `SdkInfrastructure`, the facade only as `FacadeInfrastructure` (`actions`, `configuration`, `permissions`). The facade never reads infrastructure itself: queries Push needs (`deviceId`, `hasDataForSync()`, …) are `actions.queries` (`SdkQueries`).
- `di/ActionGraph` builds the actions, split by feature: `ActionCore` (runner, remote log, API client, event bus, `InitGate`, scopes, clock) plus one `di/graph/<Feature>Graph` per `internal.action.<feature>` package. `SdkActions` is one property per feature group (`control`, `queries`, `contact`, `events`, `lifecycle`, `inApp`, `interactions`, `push`, `sync`, `inbox`, `recommendation`), each a narrow interface in its `internal.action.<feature>` package (`ContactActions`, `InAppActions`, `InboxActions`, …); `ActionGraph.actions` (`SdkActionsImpl`) holds them. Each group is implemented by a small router in `di/route/` (`ContactRouter`, `EventRouter`, …), built `by lazy` as `router` in the graph that owns it (`graph.device.router`); a router only routes facade calls onto queues and scopes, builds nothing and owns no queue. `EventRouter` is also the `LogEventQueue` of `RemoteLogRecorder`, which takes it as `Lazy` because `ActionCore` is built before the graphs. A `SerialQueue` lives (`by lazy`) in the graph of the actions it orders (`graph.init.initQueue`, `graph.inApp.inAppQueue`, `graph.recommendation.eventsQueue`); a queue shared by two features sits next to the state they share (`graph.device.contactQueue` beside `contactSession`). It can't move into an action: the order is fixed when the facade submits, before any `suspend invoke` runs. The sample app uses the public API only (debug-only hooks live in `RetenoSdkCore/src/debug`, `_interop`).

## Recipe: new Action

New actions are wired in the graph of their package (`internal.action.iam` → `di/graph/InAppGraph.kt`): one `by lazy` property per action, built from `core`, `infrastructure` and other graphs (`graph.sync.dataSync`). Every graph member is `by lazy` — the graphs reference each other in cycles (sync ↔ inbox, user ↔ start/stop), and a plain `val` in a cycle recurses into a half-built `lazy` at runtime. Read infrastructure inside the lazy (`infrastructure.db.eventsDb`); never wrap an infrastructure member in another `lazy` or alias it. A facade call is routed in the router of its group (`EventRouter`: `scope.launch { events.logEvent(event) }`) and declared on the group interface.

```kotlin
internal class LogEventAction(
    private val eventsDb: RetenoDatabaseManagerEvents,
    private val restConfig: RestConfig,
    private val eventBus: EventBus,
    private val dispatchers: RetenoDispatchers,
    private val runner: ActionRunner,
) {
    suspend operator fun invoke(event: Event): Result<Unit> = runner("LogEvent") {
        args("type" to event.eventTypeKey)
        step("save event to local database") {
            withContext(dispatchers.io) { eventsDb.insertEvents(EventsDb(restConfig.deviceId, event.toDb())) }
        }
        step("notify in-app message triggers") {
            eventBus.emit(event)
        }
    }
}
```

- **An action's logic lives in its own file.** Its constructor takes real collaborators — DB managers, repositories, controllers, `RetenoSessionHandler`, `SharedPrefsManager`, `RestConfig`, `InitGate`, `SdkConfiguration`, a platform port, `RemoteLog`, other actions — and the action calls them inside its named steps. Function-typed dependencies are only for sources of time and identity (`clock`, `jitter`, id generators). Never build behaviour in a lambda inside `ActionGraph`, a feature graph or `SdkComponent`; graphs only construct objects, the routers in `di/route/` only route facade calls onto queues and scopes. Android framework calls go through a named method of the platform port the action needs.
- One file under `internal/action/<feature>/`; `suspend operator fun invoke(...): Result<T> = runner("Name") {` on one line, or with one parameter per line when it doesn't fit in 120 columns.
- **An action reads top to bottom like its spec.** Kotlin official style, 120-column limit, 4-space indent:
  - Every `step`/`stepOrNull` body, and every `runner(...)` body, starts on a new line and the closing `}` gets its own line — never `step("…") { call() }`. A dispatcher switch inside a step stays on one line when it fits (`withContext(dispatchers.io) { eventsDb.insertEvents(...) }`).
  - A nested action (another action's `invoke`, which runs its own `runner`) is called directly, never wrapped in a `step`: it already traces its own block under the parent as `[root.n]`, and since it returns a `Result` instead of throwing, a wrapping step would always print `✓` even when the nested action failed.
  - A conditional step, nested action or step-running helper is a braced block (`if (forcePush) {` / `step(…) {` …), never `if (x) step(…) { … }` or `if (byUser) registerDevice()`; a step's result used in a condition goes into a named value first (`val inForeground = step(…) { … }`, then `if (inForeground)`).
  - When a `step(...)` call, `args(...)`, `api.request(...)`, a signature or a constructor call doesn't fit, put one argument per line; locator constructor calls that wrap use named arguments.
  - The wait for init and the server call are written in the action itself, not hidden in a shared helper; a few repeated lines are cheaper than an action you can't read in one pass.
  - One blank line after a class header and between members, none after a function's opening brace or before a closing one, never two in a row; files end with one newline.
  - Tests and fixtures follow the same layout: 120 columns (only a backticked test name may be longer), `runner`/`step` bodies on their own lines, wrapped calls one argument per line or a named `val expected`, one blank line before `whenn()` and `then()`, `SutFixture` first and `companion object` constants last. Legacy-style tests that are still waiting for their rewrite (Phase 8/10) are left as they are.
- Arguments go first inside the block: `args("type" to event.eventTypeKey)`. The start line is printed at `args(...)` (or before the first step/note/child/end if there are none); `args` called later prints a `→ key=value` note. Values are formatted only when logging is on; pass `"key" to { expensive() }` for values that are costly or need `Redact`.
- Every unit of work is a named `step(...)`. A step name says **what happens and where**: verb + object + source/destination — `"save event to local database"`, `"load unsynced devices from local database"`, `"send device to server"`, `"notify in-app message triggers"`. Never a bare verb (`"insert event"`, `"emit"`).
- Sync steps end an empty run with `nothingToSend()` (or `finishedAfter(handled)` in draining loops), so every step prints `→ nothing to send` and returns `StepOutcome.NOTHING_TO_SEND` when it sent nothing, and stays quiet (`CONTINUE`) after it drained rows. A step returning `CONTINUE` is listed in the sync summary (`sent=PushEvents, …`), so return `NOTHING_TO_SEND` whenever the run made no server call.
- Server calls are named in plain words (`"send interactions to server"`). **Never put URLs, hosts, paths, headers or bodies in step names, args, details or notes.** Never derive a step name from `ApiContract.url`.
- Anything user-related in `args` / `detail` / `note` goes through `Redact` (`token`, `email`, `phone`, `fields`, `text`, `summary`, `stackTrace`). Never format PII yourself.
- `runner(name, collapseOnSuccess = true)` buffers the action's trace, children included: a successful run whose lines are all DEBUG prints one line (`── [id] Sync  scope=ALL ✓ COMPLETED  sent=PushEvents  412 ms`), anything else (a WARN/ERROR line, an unsuccessful outcome, failure, cancellation) prints the full buffered trace. Use it only for frequent background actions (`Sync`); put what a reader needs from a quiet run into the outcome's `traceLabel`, because steps and notes are dropped.
- `runner(...)` rethrows `CancellationException`, logs `✓ SUCCESS` / `✗ FAILURE` / `⊘ CANCELLED`, and reports exactly one remote log event per failed action (no args included). A child `runner(...)` inside a parent nests automatically (`[root.n]`).
- Validation the caller must see (blank `externalUserId`, invalid `marketId`) is done synchronously in the facade before deferring, not inside the Action.
- Host callbacks are invoked via `withContext(dispatchers.main)`. Actions that answer a host `RetenoResultCallback` from a server call use `passResponseToHost` (`internal/action/inbox/HostResponse.kt`): a server failure goes to `onFailure(code, body, error)` and is only traced, never uploaded; a response that can't be read goes to `onFailure(null, null, error)` **and** fails the action, so it is reported once.
- A documented fallback is not a failure. When the host contract has one (recommendations' `onSuccessFallbackToJson`), read with `stepOrNull(…)` (`internal.action.trace`), answer the fallback callback and let the action succeed: the failed step stays in the trace, nothing is reported. Never `runCatching { step(…) }` for this: it swallows `CancellationException` and turns cancellation into the fallback.
- Operations that need the SDK configured (network, device id) wait with a named step `step("wait for sdk initialization")` inside the action instead of being gated in a facade. Actions behind the public API (`AppInbox`, `Recommendation`) wait with `initGate.awaitUserInit()`: host calls are held until `initWithConfig`, even when a configuration cached by an earlier launch already booted the SDK. Work that must run before the host initializes (push statuses, in-apps from push, sync, widget failure reports) waits with `initGate.awaitInit()`, which the cached configuration also opens. In the facade, `Reteno` methods defer with `actions.control.runAfterUserInit`, members only on `RetenoInternalFacade` (Push/FCM) with `runAfterInit`.

## Logging

- Single logcat tag `RetenoAction` for action traces, `Reteno` for uncaught scope errors. Lines are capped at 1 000 chars; the sink splits messages above 4 000.
- Logging is on only when `BuildConfig.DEBUG || Util.isDebugView()` (`isLoggingEnabled()`); when off, no message lambda is evaluated.
- `RestClientImpl` logs through the SDK log sink only method, status and a redacted error summary (`POST → 200`). Keep it that way.

## Testing

Run: `./gradlew :RetenoSdkCore:testDebugUnitTest :RetenoSdkCore:koverVerifyDebug` (filter with `--tests 'com.reteno.core.internal.*'`), `:RetenoSdkPush:testDebugUnitTest :RetenoSdkPush:koverVerifyDebug`, `:RetenoSdkFcm:testDebugUnitTest :RetenoSdkFcm:koverVerifyDebug`. Fixture self-tests: `./gradlew :RetenoSdkTestFixtures:test`.

Hard rules:
- **Never `runBlocking`.** Every test body is `runUnitTest { }` from `com.reteno.test`.
- `given()` / `whenn()` / `then()` are **required in every test**; `runUnitTest` fails the test if one is missing.
- **Fresh SUT and fresh mocks per test** via `private class SutFixture { val dep = mockk<…>(); val sut = X(dep) }`. No class-level mocks, no `@Before` state, no shared state. Global mocks (`mockkStatic`, `mockkObject`) are set up and torn down inside the test, in `try/finally` (see `UtilTest.SutFixture.withAndroid13Flags`).
- Test names are backticked sentences: `` `should abort sync when device push fails with repeatable error`() ``.
- JUnit 5 (`org.junit.jupiter.api.Test`, `Assertions`). Assert failure types with `is`.
- Robolectric tests (SQLite, Android framework behaviour) use JUnit 4 (`org.junit.Test` + `@RunWith(RobolectricTestRunner::class)` + `@Config(sdk = [26])`) — they run through the vintage engine — but still use `runUnitTest` and given/whenn/then.
- Never write a local per-test-file builder that re-lists a model's fields. Shared stub factories go into `RetenoSdkCore/src/test/java/com/reteno/core/fixtures/` (internal types) or `RetenoSdkTestFixtures` (generic helpers).
- Do not edit `RetenoSdkTestFixtures/src/main/kotlin/com/reteno/test/Test.kt` semantics without updating its self-tests.

Fixtures:
- `com.reteno.test`: `runUnitTest`, `given`, `whenn`, `then`, `TestScope.workScope()`.
- `com.reteno.core.fixtures`: `FakeLogSink` (captures `entries` / `lines`), `TestScope.testDispatchers()`, `TestScope.virtualClock()` (virtual time drives step durations), `CountingDispatcher`, `LocalHttpServer` (scripted answers, recorded requests, `connections` for `RestClientImpl`), `stubPng(width, height)`.

Mandatory coverage (contract-first): before writing code, list the checklist — happy path, every failure branch (repeatable / non-repeatable / exception), cancellation, callback thread, sync trigger, log redaction where relevant — and finish with a **Final Coverage Report** mapping each item to a test. Report gaps explicitly.

Strict TDD: red → green → refactor. A compile failure of the new test counts as red. One behaviour per test.

Coverage gate: Kover, **100 % line and branch** for the whole Core, Push and FCM modules (only generated `R`/`BuildConfig` excluded). Never add exclusions; restructure code instead. **Kover is local only — never add Kover tasks to CI.** Run `koverVerifyDebug` locally before every PR and include the result in the Final Coverage Report.

## Gotchas learned so far

- **Long-running work in tests**: no `backgroundScope` on coroutines-test 1.6.4. Launch endless loops in `workScope()`; it is cancelled before `runUnitTest` returns, so `runTest` doesn't spin forever. Drive time with `runCurrent()` / `advanceTimeBy()`, never `advanceUntilIdle()` for such work.
- **Exception identity**: Gradle runs tests with assertions on, which enables coroutines stack-trace recovery — exceptions crossing a suspension point are re-created with the original as `cause`. Don't `assertSame` exceptions that crossed `withContext`/`launch`; assert type and message. Production code that matches exceptions must compare cause chains on both sides: an error thrown inside `withContext` within a step is copied at every boundary, and the copies only share the original as `cause` (see `ActionTraceImpl.failedStepOf`).
- **Unreachable Kotlin branches fail the 100 % branch gate**: `x?.let { nonNull } ?: y`, `x?.toString() ?: y` and `a?.b?.c ?: d` with a non-null `b` compile to branches no test can reach. Use `val v = x ?: return y` or an explicit `if`.
- **Loops that only end by cancellation create unreachable branches**: `while (isActive) { …; delay() }` and `for (x in channel)` (channel never closed) each have an exit branch no test reaches. Use `while (true)` with a cancellable suspension (`delay`, `channel.receive()`).
- **`when` over a nullable enum** (`when (result.getOrNull()) { …, null -> }`) adds a branch Kover can't see covered; unwrap first (`val x = … ?: return fallback`) and `when` over the non-null enum.
- **`when (x) { is A -> …; is B -> … }` over a sealed *interface* compiles an extra `else` branch** that no test can reach. Handle one case and return early, then cast: `if (response is ApiResult.Failure) { …; return }; val body = (response as ApiResult.Success).body`.
- **`BuildConfig.DEBUG` is not a compile-time constant** (`Boolean.parseBoolean`), so `BuildConfig.DEBUG || x` has a branch the debug unit-test variant can't cover. Pass it as a defaulted parameter (`isLoggingEnabled(debugBuild = BuildConfig.DEBUG, …)`) and test the parameters.
- **Kover instrumentation breaks JUnit 3's `TestCase.assertEquals`** (AIOOBE) used by some legacy tests; `kover { excludeInstrumentation { packages('junit.framework', 'org.junit', 'org.robolectric', 'io.mockk') } }` is required in every module applying Kover.
- **Never mock a concrete SDK class.** Creating a mock of a class retransforms its bytecode and drops the Kover hits other tests recorded for it in the same JVM, so the gate fails depending on test order (found with `InitGate`, again with `DataSync`). Anything other code depends on and tests need to replace has an interface in the same file: actions get one named after the operation (`RegisterDevice` implemented by `RegisterDeviceAction`), other collaborators a role interface (`SdkConfiguration`/`SdkConfigurationImpl`, `SyncScheduler` implemented by `DataSync`). Dependents take the interface; tests mock the interface. Small value holders like `InitGate` stay concrete and are used for real in tests.
- **Core runs Robolectric (JUnit 4) tests in their own JVM.** `testDebugUnitTest` runs only the JUnit 5 engine and is finalized by `testDebugRobolectricUnitTest` (JUnit vintage engine, same classpath, Kover's agent copied in, appending to the same `.ic`); the Kover report tasks depend on both. Before the split, Robolectric's sandbox copy of a class made Kover drop the hits plain JUnit 5 tests recorded on the other copy (found with the old locator's `backgroundSync`). Keep a class's tests in one runner anyway: Robolectric only for thin Android adapters (plan 10d target), plain JUnit 5 for logic.
- **Mocking a concrete class drops its Kover hits** (`mockkObject` / `mockkStatic` / `mockk<Concrete>()` retransform the bytecode), across every test in that JVM — the legacy `RetenoTestApp` mocks of `Util` / `Logger` cost 48 lines of whole-module coverage. New tests never mock concrete SDK classes; `Logger` is replaced with `Logger.install(FakeLogSink(), …)` in `try`/`finally`. The one exception: a concrete Android adapter covered only by Robolectric tests (`SharedPrefsManager`, `FileManager`) may be mocked in JUnit 5 tests, because the retransform stays in the other JVM.
- **Gson allocates classes without a no-arg constructor without running any constructor.** Their constructor lines stay uncovered and non-null fields can be `null`. Response models get defaults on every field (`val messages: List<…> = emptyList()`), so Gson calls the generated no-arg constructor and a missing field reads as empty.
- **Kotlin inlines enum `.name` and `const val`s.** An enum used only as `X.Y.name`, or an `object` holding only constants, is never loaded, and its declaration line stays uncovered. Use `private const val` strings or top-level constants instead.
- **Public models using `android.util.Pair` (`Order.attributes`) can only be built under Robolectric.** Their tests (`EcomEventMapperTest`, `OrderTest`) are Robolectric; everything else in models and mappers is plain JUnit 5.
- **Mapper tests read every mapped field** (`listOf(remote.a, remote.b, …)` against an expected list), not `assertEquals(dataClass, dataClass)`: data-class `equals` compares fields without calling getters, so getters of Gson-only models would stay uncovered and a mis-mapped field could hide behind a matching default.
- **Core facade tests** construct `RetenoInternalImpl` through its internal constructor (`FacadeInfrastructure`) with `FakeFacadeInfrastructure(FakeSdkActions())` and a `ManualLifecycleOwner`; the facade defers through `actions.control.runAfterUserInit` (public API) or `runAfterInit` (Push/FCM members), `FakeSdkControl` holds those operations in one list, and tests release them in order with `actions.control.markInitialized()` (by the host) or `markInitialized(byUser = false)` (cached configuration: releases only `runAfterInit` operations). `FakeSdkActions` is one fake per group (`FakeContactActions`, `FakeInboxActions`, …) writing to one shared `FakeCallLog`, so `actions.log.calls` keeps the order across groups; feature facade tests use only their group fake (`FakeInboxActions(log)`). The real wait lives in `InitGate.runAfterInit` / `runAfterUserInit(scope, operation)` (call order, run at once after init, the scope's dispatcher — `InitGateTest`); `InitRouter` only forwards it with the main scope (`ActionGraphInitWiringTest`). No gated class (`InitGate`, `LifecycleEventFilter`, `ActionGraph`) is loaded in those Robolectric tests.
- **Nothing builds the SDK on unsupported OS (API < 26), and only `SdkComponent` knows the OS.** `SdkComponent.actions` is `ActionGraph.actions` on a supported OS and `UnsupportedOsActions` (one null object per group, in one file: operations ignored, `runAfterInit` drops the operation, safe answers for queries, `applyUserConfig` only keeps the config) below it. Facades (`RetenoInternalImpl`, `AppInboxImpl`, `RecommendationImpl`) never check the OS; synchronous validation runs on every OS. A new group member gets its no-op/safe answer in the group's null object in `UnsupportedOsActions`, a recording in the group fake, and a line in `UnsupportedOsActionsTest`.
- **Tests of debug-only code live in `src/testDebug`.** `src/debug` classes don't exist in the release variant, so a test in `src/test` breaks `testReleaseUnitTest` (CI only runs debug).
- **`SdkComponent` keeps gated collaborators lazy** (`LifecycleEventFilter`, `SdkConfigurationImpl`, `ActionGraph`), so its Robolectric test (one instance per collaborator) never loads them into the sandbox.
- **Push and FCM reach the SDK only through `RetenoInternalEntryPoint.facade`** (`RetenoInternalFacade`, opt-in `@InternalRetenoApi`; modules opt in with `-opt-in=com.reteno.core.InternalRetenoApi`). Never `Reteno.instance` there. Push tests install `FakeRetenoFacade` with `withFakeFacade { }` (FCM tests a relaxed `mockk<RetenoInternalFacade>()`), which restores the SDK instance in `finally`. A new Push need is a new facade member, implemented in `RetenoInternalImpl` by deferring to a `submit*` of the group it belongs to (`actions.push`).
- **`StateFlow.first {}` waiters are not resumed in FIFO order** once collector slots get reused, and two `CompletableDeferred`s resume all waiters of the first before any of the second. `InitGate` therefore keeps held operations of both kinds (`runAfterInit`, `runAfterUserInit`) in one list and launches the ready ones in call order on their scope; a call arriving while released operations have not run yet is launched behind them instead of running at once, so nothing overtakes calls made before init. `awaitInit` / `awaitUserInit` (used inside actions) stay plain deferred waits.
- **Tests that start the SDK also start the sync scheduler** (every 30 s; every 10 s when the config has debug on, as the sample app's debug build does). `ActionGraphFixture` gives `ActionGraph` a `workScope()`-backed scope so such loops are cancelled when the test ends; never hand it a free-standing scope on the test dispatcher.
- **Every Robolectric SDK level is its own sandbox, and the last sandbox to load a class wins in Kover.** Push tests at `sdk = [22]`/`[31]` next to `[26]` dropped the `[26]` hits (coverage fell to ~70 %). Keep each module's gated classes in one sandbox (`@Config(sdk = [26])`) and cover version branches by pinning `Build.VERSION.SDK_INT` with `onAndroidSdk(sdk) { }` (`ReflectionHelpers`, restored in `finally`). Pin only code that doesn't call newer framework methods — e.g. build a `NotificationCompat.Builder` inside the pin but call `build()` outside it, or you get `NoSuchMethodError`. Robolectric 4.8.1 has no API 33, so Android 13 branches are pinned too.
- **Robolectric merges the library manifest into Push/FCM tests**: Push meta-data (`com.reteno.Receiver.*`) and receivers are visible to tests. Change meta-data through `shadowOf(packageManager).getInternalMutablePackageInfo(packageName).applicationInfo.metaData` (`applicationMetaData()` fixture); make a launch activity resolvable with `registerLaunchActivity()` (resolve info **and** `addActivityIfNotPresent`, or `checkActivities(true)` rejects the explicit launch intent).
- **`@JvmStatic` members of an `object` are static calls**: `mockkObject(Util)` doesn't intercept `Util.readFromRaw`; use `mockkStatic(Util::class)`.
- **Always `disconnect()` an `HttpURLConnection` you abandon** (size limit, early return). A connection left open kept the local test server blocked in `write` and hung the whole Push test task; test servers answer each socket inside `runCatching`.
- **Android unit tests compile against `android.jar`**: no `java.awt`, `javax.imageio` or `com.sun.net.httpserver`. Serve test HTTP with a `ServerSocket` and embed images as bytes.
- **Inline functions add their branches to the caller**: `fromJsonOrNull` (`isBlank()`), `runCatching { }.getOrNull()`, `orEmpty()` count as branches of the calling class, at every call site. Funnel them through one private function (`parseChannelData`) so one pair of tests covers them.
- **A view's UI scope is no place for persistence.** UI work is cancelled when the app goes to background (the in-app readiness wait on `pause()`), so a recording launched there can be lost; views hand interactions to `InteractionSubmitter` (`InteractionRouter` on the SDK's long-lived scope).
- **Contact operations run through `graph.device.contactQueue`** (`SerialQueue`), so user/device updates are applied in call order. Validation that must reach the caller (`UserAttributesValidator`) runs in the facade *before* enqueueing.
- **Don't switch Kover to JaCoCo** (`useJacoco()`): it doesn't filter coroutine state-machine branches and reports dozens of unreachable branches in every suspend function.
- **`testFixtures` is a reserved Gradle dependency method** — the shared fixtures dependency group in `test_dependencies.gradle` is called `retenoTestFixtures()`.
- Kotlin modules can't see another module's `internal` declarations, so fakes of internal SDK types live in `RetenoSdkCore/src/test/.../fixtures`, not in `RetenoSdkTestFixtures`.
- **A non-const `val` in a `private companion object` leaves an uncovered accessor line.** Use `const val` for primitives and build objects (`LocalTime.of(...)`) where they're used.
- **Android views sit behind a gated port with an ungated adapter.** `InAppPresenter` (`internal.iam`, plain JUnit 5) drives the in-app through `InAppScreen`; `AndroidInAppScreen` (`view/iam`, Robolectric, not gated) owns WebView containers, the JS bridge and activity callbacks; tests use `FakeInAppScreen` (also via `FakeAppPlatform.screen`). Keep the logic in the presenter so the gate never needs a Robolectric test of a gated class.
- **`delay` on a test dispatcher wrapper needs `Delay`.** A `CoroutineDispatcher` that wraps the test dispatcher without implementing `Delay` makes `delay` fall back to real time (the presenter's readiness wait never advanced). `MarkingDispatcher` delegates `scheduleResumeAfterDelay` to the test scheduler and keeps the marking; do the same in any new wrapper.
- **Gson leaves declared non-null Kotlin fields null** (missing key, enum value this SDK doesn't know). Where the old code had a fallback, read the field into a nullable local (`val layoutType: InAppLayoutType? = content.layoutType`) and apply it; test with JSON parsed through Gson, not a constructed model.
- **Every class Gson reads needs an R8 keep rule.** Consumer rules keep only `com.reteno.core.data.remote.model**` and `com.reteno.core.features.iam**`. Parse JSON into a model with `@SerializedName` fields in one of those packages, never into a private class in `internal.*`: minified host apps rename its fields and Gson fills nothing, which unit tests can't catch. Host classes Gson fills for the SDK (`RecomBase` implementations) are kept by a consumer rule too; check such changes with a release build (`./gradlew :app:assembleRelease -x lintVitalRelease`), unit tests run unminified.
- **Guard host callbacks that sit inside a state change.** A host exception must not skip the state update around it (the in-app presenter reports it through `RemoteLog` with the callback name and exception class only, and carries on).
- **Broadcasts carrying data stay in the app.** Use `AppBroadcaster.sendToApp` (`setPackage(packageName)`) for anything with extras; `send` (no extras) still reaches every matching receiver.
- **Starting the SDK in a locator wiring test now fetches in-app messages** (and the first foreground preloads the base html). `FakeRestClient` answers in call order, so script answers for a specific endpoint with `rest.succeedWith(contract, body)` instead of relying on queue order.
- **Don't `getOrThrow()` a child action's result** to fail the parent: the child already reported its failure, so the parent would report a second one. Ignore the result (it is traced) unless the parent must stop.
- **Subscribe to a `SharedFlow` without replay with `launch(start = CoroutineStart.UNDISPATCHED)`** when events emitted right after the call must not be lost (`InAppTriggers.listen`); a normal `launch` subscribes only when the coroutine first runs.
- **`ActionGraph` properties carry explicit types** (`val events: EventGraph by lazy { … }`). `core` is built with `lazy { events.router }`, so an inferred type sends the compiler round the cycle ("Type checking has run into a recursive problem").
- **Never give a collaborator property the name of a member function.** In `DataSync`, `private val clearOldData: ClearOldDataAction` next to `fun clearOldData()` made `clearOldData()` inside the class call the member function, not the action, so it relaunched itself every 3 s forever. Name action properties after the action (`clearOldDataAction`).
- **`step` infers `T` from the action's return type.** In `suspend operator fun invoke(): Result<Unit> = runner("X") { step("…", detail = { "n=$it" }) { count() } }` the last step becomes `step<Unit>` and `detail` prints `kotlin.Unit`. Pin it: `step<Int>(…)`.
- **A nullable callback that is always set when reached** (`callback?.invoke()` after a guard that implies it's set) is an unreachable branch. Unwrap it earlier, on a path tests do reach: `val show = callback ?: return`.
- **Android framework access goes through four narrow platform ports** (`internal/platform/`, interface and Android class in one file): `AppEnvironment` (installed version, device description, log-event origin, bundled widget), `AppBroadcasts` (implemented by `AppBroadcaster`), `HostUi` (activity tracking, lifecycle and fragment watchers, top package, in-app screen) and `BackgroundWork` (WorkManager). A consumer takes only the ports it uses; a new Android fact goes into the port whose callers need it, never a new catch-all. The Android classes are tested with Robolectric (`AndroidAppEnvironmentTest`, `AndroidHostUiTest`, `AndroidBackgroundWorkTest`); actions and `ActionGraph` get `FakeAppPlatform` (implements all four), never a `Context`.
- **Push/Fcm tests can't see Core `internal` types** (`ActionGraph`, `DataSync`, …). Push tests verify what Push calls on the facade; Core's `RetenoInternalImplTest` verifies what the facade does with it. Push and FCM tests are all Robolectric (JUnit 4) — don't mix plain JUnit 5 tests of the same classes in, see the sandbox rule above.
- `SdkComponent` owns `ActionGraph` (`component.actions` is its router). Legacy repositories/controllers that must trigger a sync take plain function types (`requestSync: () -> Unit`, `syncContactNow: suspend () -> Unit`), never internal types, because several of those legacy classes are `public`.
- Everything persisted as a remote log event goes through `RemoteLogRecorder` (built by `ActionCore`, installed into `Logger` by `ActionGraph.installLogging()`; tests never call it, so the global stays clean), which applies `Redact.uploadable` / `Redact.uploadableStackTrace` (values after `=` and URLs/hosts are dropped). Don't create `RetenoLogEvent`s yourself; record through `RemoteLog` or `Logger`.
- **Code that reads or writes the log-event tables mutes the remote log** (`RemoteLogGuard.muted { … }` inside its `withContext(dispatchers.io)`): the frozen DB layer logs its own failures through `Logger.e`, which would otherwise record a new log event from inside the log-event pipeline.
- **`bufferedReader()` / `bufferedWriter()` are inline and add an `is Buffered*` branch** no test reaches when called on a plain stream. Use `InputStreamReader` / `OutputStreamWriter` with `try`/`finally` (`RestClientImpl.readText`).
- **The desktop JDK refuses to write a request body unless `doOutput = true`** (Android documents the same). Tests of network code run on plain JUnit 5 against `LocalHttpServer`; map the contract URL onto it with `server.connections`.
- **Android API-level branches on plain JUnit 5:** `Build` fields are `0`/`null` there. Put the branch in an `internal` overload taking `sdkInt` (`getApplicationMetaData(sdkInt)`, `isSupportedSdk`) and test it with mocked framework objects; static factories of newer APIs (`PackageManager.ApplicationInfoFlags.of`) are `mockkStatic`ed in `try`/`finally`. Robolectric 4.8.1 can't load API 33 classes at all.
- **Robolectric's `ShadowBitmap` rejects a 0-pixel scaled size like a device does** (`IllegalArgumentException`), so a 1×4000 `stubPng` exercises `BitmapUtil`'s keep-the-original fallback.
- **`Logger` replays remote-log records buffered before `install`.** A test that asserts on its `FakeRemoteLog` installs it with `Logger.installCapturing(sink, remoteLog)` (fixtures), which drains records left by earlier tests first; plain `Logger.install(…)` makes such assertions depend on test order.
- **Robolectric's API 26 `ActivityLifecycleCallbacks` has no `onActivityPreCreated`.** Calling it through the interface type throws `NoSuchMethodError`; give the callbacks a concrete class type (`RetenoActivityHelperImpl.LifecycleCallbacks`) and call it on that.
- **Permission flows under Robolectric:** answer a launched request with `activity.onRequestPermissionsResult(shadowOf(activity).lastRequestedPermission.requestCode, …)`; an "already granted" answer is posted to the main looper (`ShadowLooper.idleMainLooper()`); `controller.recreate()` restores pending activity-result keys into the new instance.
- **Constructing the real SDK in a test:** pin the OS below the supported minimum (`onAndroidSdk(25) { Reteno.create(app) }`, fixtures) so `RetenoInternalImpl` and `SdkComponent` are built without booting; otherwise use the internal constructor with `FakeFacadeInfrastructure`. Restore `Reteno.instanceInternal` (and `Logger` after touching `SdkComponent.actions`) in `finally`.
- **WorkManager is a JVM-wide singleton**: tests of `appWorkManager` reset `WorkManagerImpl.sDefaultInstance` / `sDelegatedInstance` with `ReflectionHelpers` before and after.
- **A Robolectric `WebView` always measures 0 × 0.** Size-dependent view logic goes into a pure function tested on JUnit 5 (`slideInStart`); touch behaviour is tested on a clickable plain `View` with fixed size (it consumes the `DOWN` like a WebView, so the behaviour sees the following `MOVE`s through `onInterceptTouchEvent`).
- **Driving `ViewDragHelper` in Robolectric:** send `MotionEvent`s to the parent with times from `SystemClock.uptimeMillis()` and `ShadowSystemClock.advanceBy`; the touch slop (~36 px at 10 steps) is not added to the drag, so drag well past the threshold. Hold still ~300 ms before `UP` for a zero-velocity release, release right after moving for a fling, and settle with repeated `ShadowLooper.idleMainLooper(16, MILLISECONDS)`.
- **Robolectric's window manager is shared by every activity in a test**: filter `ShadowWindowManagerImpl.views` (popup windows by class name) and check each popup before showing the next.
- **In-app containers are created through `IamContainerFactory`** (`AndroidIamContainers` in production); `AndroidInAppScreen` guards every container call (`create`, `present`, `resize`, `hide`, `destroy`) and logs the failure, so containers keep no try/catch of their own.
- **Android SQLite `insert()` never throws**: it logs, returns `-1` and the transaction commits the other rows (`insertMultiple` gives `[1, -1]`). Only `query` / `rawQuery` / `delete` / `execSQL` / `beginTransaction` throw, so test `RetenoDatabaseImpl`'s failure handling through those (a dropped table, a closed database).
- **Read `NOT NULL` and `INTEGER PRIMARY KEY` columns with `getString` / `getLong`, nullable ones with `getStringOrNull`.** A null check on a column the schema can't leave null is an unreachable branch (and `getStringOrNull` is inline, so it adds one at every call site). Cover each nullable read with one row that has the value and one that doesn't.
- **Migrations add a column only when it is missing** (`ColumnMigration` in `RetenoDatabaseImpl`, checked with `PRAGMA table_info`): `onUpgrade` first creates missing tables with today's columns and `mitigate` reruns every migration, so a blind `ALTER TABLE` reported a "duplicate column" error on every upgrade. Only failures for another reason are logged; `RetenoDatabaseImplTest` asserts upgrading every released schema reports nothing.
- **A stored row that throws while being read is unreadable, not fatal** (`readRows` catches per row): it is removed like a row with missing required columns, and the rows after it are still read. Don't log the parse exception itself, its message can quote stored data.
- **Upgrade tests use the real released schemas, never hand-written "old" tables.** `src/test/resources/database/history/vNN_<commit>.sql` holds the exact `CREATE` statements of every distinct released schema (extracted from git; one version can have several schemas). When a schema or migration changes, add the new released schema there and keep `RetenoDatabaseImplTest`'s fresh-install and upgrade checks green: no column may move, every current column must exist after upgrading.
- **DB tests run on real SQLite through `TestDatabase.open { }`** (fixtures; Robolectric, fresh database, `Logger` captured into `remoteLog`). Insert broken rows with raw SQL (`db.execute(…)`), set a known `timeStamp` with `stampRows`, and assert stored state with `db.values("SELECT …")`. Upgrade tests load a released schema with `storeReleasedDatabase(name, rows…)` (reads the history file, stores its version and rows); `storeOldDatabase` is only for deliberately broken or future databases (a newer version, a table left as a view).
- **`InAppMessageDb.segment` is a body `var`, so data-class `equals` ignores it** — assert segments separately. A null in-app `model` is stored as the text `"null"` (old rows have it too); keep reading it as stored.
- **Mutation checks: run each build with `--no-watch-fs` and rewrite (never rename) the file to restore it.** With file-system watching on, Gradle missed source edits made right before a scripted build and reused the previous classes, so mutants ran on top of earlier ones or not at all. `./gradlew :RetenoSdkCore:clean` before a mutation run, and check the sources' checksum after it.
- **`RetenoLogEvent` default arguments read `Build` through `DeviceInfo` and leave `version` null.** Build events with explicit `osVersion`/`version`/`device` (from `AppEnvironment.logEventOrigin()`) in new code and tests; `RemoteLogRecorder` fills a missing `version`.
- **Android answers an overlapping permission request at once with empty results** ("one set at a time"), so the second caller would read `false`. `AndroidPermissionChecker` serialises requests with a `Mutex`; `LauncherContext` forgets its pending continuation when the request is cancelled or `launch` throws, so a later dialog answer or `abandon()` never resumes a finished coroutine.
- **Activity state is read on the main thread.** `PermissionActivityDelegate.requestChecker()` switches to the injected main dispatcher before polling (the host may call it from any thread); test it with `testDispatchers().main` and a probe activity reading `markedMain.isRunningHere`.
- **Animation callbacks posted to a view outlive its parent.** `SwipeDismissBehavior` keeps the `ViewDragHelper` captured at release for the whole settle; never look it up again through `child.parent` inside `postOnAnimation` (null once the in-app is removed mid-swipe).
- **Android's regex engine (ICU) is stricter than the JVM's**: an unescaped `}` (`Regex("\\$\\{.+}")`) compiles in unit tests but throws `PatternSyntaxException` on a device, and in a companion `val` it fails class init (the whole SDK init failed this way). Escape every literal `{` and `}`; unit tests can't catch it, a device smoke run does.
- **Events whose order matters are logged sequentially from one coroutine.** One `scope.launch { logEvent(…) }` per event let `SessionStarted` be stored before `SessionEnded`; `SessionTracker.tick()` returns the events and its loop logs them one by one.
- **A device is saved with the notification state read from the system.** `CurrentDevice.save` without an explicit `pushSubscribed` reads `AppEnvironment.notificationsEnabled(channelId)` (app notifications **and** the default channel, the same rule as Push's `NotificationsEnabledManager`; channel id from the stored channel JSON, else `defaultId`) and falls back to the stored state if the read throws. Saving with the stored default (`false` on a fresh install) made Push's first state report change the device and send it a second time; now that report saves an identical device, which `CurrentDevice` skips.
- **The `RemoveWorkManagerInitializer` lint check reads only the app's own manifest.** The SDK's manifest already removes `WorkManagerInitializer`, but an app implementing `Configuration.Provider` (the sample) needs the same `tools:node="remove"` entry, or `lintVitalRelease` fails the release build.
- **Never interpolate a result object into a trace.** `TracedOutcome.traceLabel` defaults to `toString()`, and a data class `toString()` prints every field (`ApiResult.Success` printed response headers with `Set-Cookie`, `Failure` the host inside the exception). A `detail` that adds to an outcome prints `${it.traceLabel}`, never `$it`. `ApiResult` redeclares `traceLabel` abstract, so a new result type must give a safe label; inheriting the default would also leave an uncovered `DefaultImpls` bridge.
- **A null `whereArgs` value binds as SQL `NULL`** (`SQLiteProgram` keeps the `Object[]`), so `row_id=?` with a null id matches nothing and `delete` answers 0 — it does not throw. Don't add guards for it; the manager tests pin it.
